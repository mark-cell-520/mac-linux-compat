# 落地手册

日期：2026-11-06

## 一、本机运行（当前形态）

```bash
# 构建（唯一依赖：Xcode 命令行工具自带的 clang）
clang -O2 -Wall -o mlc-core ~/Pictures/mac-linux-compat/src/mlc-core.c

# 跑一个位置无关 Linux ARM64 静态镜像
./mlc-core <镜像路径> [参数...]

# 带系统调用追踪
MLC_DEBUG=1 ./mlc-core <镜像路径>

# 完整验证（十一项）
bash ~/Pictures/mac-linux-compat/tests/verify.sh
```

## 一补、客户机地址空间约束（v1.1 起，改动客户机可观测行为）

引擎维护客户机内存区域表（加载段、客户机栈、brk 增长区、每次 mmap 区间）。
由此产生的行为变化，写客户机程序的人必须知道：

1. 野指针不再崩宿主：读写未注册区间返回 -EFAULT，字符串路径返回 -EFAULT。
2. mprotect / mmap(MAP_FIXED) / munmap 的目标区间必须已注册，否则返回
   -ENOMEM / -ENOMEM / -EINVAL。客户机不能在未映射地址上建 MAP_FIXED 映射，
   也不能 mprotect 自己区间之外的地址（这是防改写翻译层的硬约束）。
3. munmap 未按宿主 16K 对齐时，宿主只卸中间完整页，页内残余变 PROT_NONE；
   客户机区间之外的字节不受影响。
4. 单次 I/O 长度上限 1GiB，超过按 -EFAULT 处理。
5. 客户机 mmap 到新地址是允许的（非 MAP_FIXED），返回地址自动纳入区域表。

## 二、镜像要求（重要）

v1 只接两类镜像：
1. ET_DYN 且全位置无关（static-PIE）：直接可跑。
2. 段保护不同的相邻段不能落入同一宿主 16K 页：用 `-Wl,-z,max-page-size=16384` 链接可保证。

不接：
- ET_EXEC 非 PIE 静态镜像（如 Ubuntu 官方 busybox-static）：引擎会明确报错并提示，M2 做基址重写后再支持。
- 动态链接镜像（需要 ld.so 与 rootfs）：M2。
- 客户机段 4K 对齐且异保护段相邻：报错提示同上。

## 三、自制测试载荷的方法

```bash
clang -c -target aarch64-linux-gnu -o test.o test.s   # clang 兼任汇编器
python3 ~/Pictures/mac-linux-compat/tests/mkelf.py test.s test.elf
```
test.s 须全 PC 相对寻址（adrp/add :lo12），mkelf 负责重定位与 16K 对齐。

写新用例的注意：断言不能依赖 /tmp 的既有内容（F08 的教训），
目录列举一律指向自建子目录；野指针用例要选引擎直接解引用内存的系统调用
（如 clock_gettime），否则宿主 errno 会让假绿蒙混过关（见 docs/05 第三节）。

## 四、卸载

整目录删除即可，无系统残留：
```bash
rm -rf ~/Pictures/mac-linux-compat
```
交付物未向 /usr/local、~/Library、launchd 写入任何东西。

## 五、已知边界（交付时必须随附）

1. MLC 不是沙箱：客户机以本进程权限直接操作宿主文件系统与进程（安全审核 R1）。
   v1.1 起客户机碰不到自己映射之外的地址，但不改变"能调用全部已实现系统调用"这一属性。
2. 未实现：动态链接、非 PIE、多线程、信号、网络、ptrace 类程序、GPU。
3. futex 恒返回 0：多线程客户机可能死等，M3 实现真实 futex 前不要跑多线程程序。
4. 性能：系统调用每次经存根与 C 分发，吞吐低于原生（未做基准测试，不做数字声明）。
5. 大镜像 >128MB 时加载期直接报错（BL 越界已改为显式失败，不会跳飞）。
6. 客户机 mmap MAP_FIXED 到未注册区间会被拒（-ENOMEM），与真实 Linux 行为不同；
   这是防改写翻译层的取舍，见 docs/07 R7 与 docs/10 D8。

## 六、路线图衔接

M2 动态链接 + 非 PIE 基址重写 → M3 线程/信号/网络 → M4 一键安装包与 rootfs 路径重写 → M5 GUI → M6 原生 Rust 翻译层预研。


## v1.3 落地变更（2026-11-06）

1. rootfs 形态变了：仓库只带 29MB 的 tarball，103MB 的 sysroot 按需解出。
   MLC.command 与 src/install.sh 都会自动调 scripts/unpack-rootfs.sh，
   手动安装时若忘记，verify.sh 的动态链接冒烟会失败并提示缺 rootfs。
2. 验证项从 15 变 21，安装门禁随之变严。任一项失败即中止安装。
3. 新增 tests/stability.sh，只报告不判定。已知缺陷 K1（动态链接错误路径
   2% 到 5% 偶发失败）是概率性的，进门禁会让一键安装随机失败，
   所以它单独放，见 docs/10 的 K1 节与 D18。
4. 卸载口径不变：删项目目录 + ~/.local/bin/mlc。若还要回收空间，
   再删 rootfs/sysroot 与 rootfs/ubuntu-base-arm64.tar.gz。
