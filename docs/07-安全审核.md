# 安全审核

日期：2026-11-06
审核人：主会话（心虫在线时请复核）

## 一、威胁模型

MLC 在本机用户态运行，把 Linux 客户机程序的系统调用翻译后以本进程权限执行。
这意味着：客户机的破坏力 = 宿主持有者的破坏力。安全边界比虚拟机弱得多，必须明示。

## 二、已识别风险与处置

R1（高，设计固有）：客户机可调用全部已实现系统调用，操作真实宿主文件系统与进程。
处置：文档明示"MLC 不是沙箱"；不提供网络暴露面；建议只运行可信镜像。
后续缓解（M4）：可选的路径前缀重写（把客户机 / 映射到项目内 rootfs 目录），需要 proot 式路径拦截，本期不做。

R2（高）：未校验的客户机指针可致宿主进程崩溃。
处置：v1.1 已修复。机制见下节"客户机地址空间约束"。

R7（中，v1.1 新增识别）：客户机可用 mprotect 改引擎自身映射（含蹦床）为可写，
从而改写翻译层代码；也可 mmap MAP_FIXED 到宿主任意地址覆盖引擎映射。
处置：v1.1 已加约束——mprotect/mmap-FIXED/munmap 只准作用于客户机已注册区间，
越界返回 ENOMEM/EINVAL，客户机无法触及蹦床与引擎映射。

R8（低，v1.1 新增识别）：区域表容量 G_REGION_MAX=128 写满后 region_add 静默跳过，
后续映射不纳入校验。当前实现是"安全侧失败"：未注册区间的访问一律返回 EFAULT，
客户机功能受损但不会获得越权访问。达到 128 个区间需客户机高频 mmap/munmap，
正常程序不会。
处置：写满时打警告；不改为"放行"，避免把容量问题升级成安全问题。

## 三、客户机地址空间约束（v1.1 新增机制）

引擎维护一张客户机内存区域表 [start, end)，记录加载段、客户机栈、brk 增长区、
以及每次 mmap 实际映射的区间。客户机指针与宿主指针同值（无地址重定位），
因此"是否可访问"可以精确判定：

1. guest_ptr_ok(addr, len)：[addr, addr+len) 必须完整落在某个已注册区域内，
   否则返回 -EFAULT。字符串走 guest_str_ok：区域内以 NUL 结尾才算合法。
2. mprotect / mmap(MAP_FIXED) / munmap：目标区间必须已注册，否则拒绝。
   这把"客户机只能动自己的内存"变成了硬约束，蹦床与引擎代码因此不可被改写。
3. munmap 精确卸载：宿主按 16K 页卸载中间完整页，页内残余 mprotect PROT_NONE，
   避免顺手卸掉同一宿主页内相邻的客户机映射（区域表同步裁剪）。

反向验证：把 region_covers 临时改为恒真后，野指针测试载荷立即以 SIGSEGV 崩溃
（退出码 99），证明该校验真实生效，不是宿主 errno 的巧合。

R3（中）：蹦床代码注入可执行内存。BL 目标由本程序计算，立即数修补点固定，客户机无法影响蹦床内容；但客户机数据段与蹦床同进程地址空间。
处置：蹦床映射 RX 不可写；客户机段与蹦床分离映射。

R4（中）：W^X 规避路径。本机禁 RWX，引擎用"先 RW 写入再 mprotect RX"的两步法，写入窗口内代码页可写。
处置：窗口仅存在于加载期，加载完成后无可写执行页。

R5（低）：系统调用追踪（MLC_DEBUG）会把参数打到 stderr，可能泄露路径等内容。
处置：仅调试用途，默认关闭。

R6（低）：测试载荷 /tmp/mlc-test.txt 等临时文件可预测路径。
处置：测试专用，不进入交付运行路径。

## 三、代码执行安全

- 无动态代码生成（除蹦床一次性写入）。
- 无 shell 调用、无 eval、无外部命令执行。
- 无网络监听、无数据外传。
- 无遥测。

## 四、审核结论

v1.1 在"运行可信静态位置无关镜像"的场景下安全可控。R1 为兼容层路线的固有属性
（CrossOver/Wine 同样如此），必须以文档形式随交付物明示，不得作为沙箱宣传。
R2 已于 v1.1 修复并经反向验证；R7 的地址空间约束同期限定。其余风险有处置或可接受。

心虫复核重点：R7 的约束是否过紧（客户机 mmap 到未注册区间会被拒，真实 Linux 允许），
以及 R8 表满时的降级方向（当前选功能受损而非放行）。


## v1.3 安全复审（2026-11-06）

本轮审计新增一条与安全直接相关的发现，已修（F37）：

客户机可控输入 → 宿主内存破坏。
main() 里 strptr[256]、envptr[160]、words[600] 三个数组位于宿主栈，
其中 argv 条数没有任何上界检查。运行 `mlc $(seq 1 500)` 即越界写宿主栈。
这是全项目第一条「客户机输入直接决定宿主写边界」的路径，此前只防了
客户机指针（区域表 + EFAULT），没防客户机参数个数。
修法：三个数组设硬上限、超限报用法错误退出、初始栈词数先算后写。

另修掉两条让既有防护失效的簿记缺陷：
1. mremap 的 region_del 区间与 munmap 不一致，区域表残留已释放条目，
   野指针校验对已卸载地址放行（F38）。
2. 两条 MAP_FIXED 路径先 munmap 再 mmap，mmap 失败时区域表未同步，
   表里声称可访问而实际已卸载（F49）。

由此确立一条口径并写进 README：引擎的防护强度等于区域表的可信度，
所以「簿记不说谎」本身就是安全属性，不是代码整洁问题。

既有边界不变：MLC 不是沙箱，只运行可信镜像。
